# Data Model (core entities)

## Workspace
- Belongs to a developer / team
- Has its own credit balance, billing details, members
- Contains agents, tools, knowledge, end users

## Agent
- Belongs to a workspace
- Has a configuration: tools assigned, knowledge assigned, default model tier, scoping rules
- Can be invoked on-demand, scheduled, or triggered by webhook

## Tool
- Belongs to a workspace
- Definition includes name, description, parameters schema, execution endpoint
- Can be assigned to one or more agents
- Editable in dashboard

## Knowledge
- Belongs to a workspace
- Can be a document, a structured dataset, or a connected source
- Can be assigned to one or more agents
- Editable in dashboard

## End User
- Belongs to a workspace
- Identified by user ID (chosen by developer, opaque to Midsphere)
- Optional metadata (display name, tier label, custom fields)
- Has per-user controls: credits, run counts, sandbox time, concurrency, model tier, tool access, knowledge access
- Has wallet refresh schedule

## Run
- An invocation of an agent for a specific end user
- Captures: prompt, plan, executions, tool calls, artifacts produced, cost, duration, rating
- Belongs to a workspace, agent, end user
- Can be scheduled or on-demand

## Schedule
- Defines when an agent should run
- Cron-style schedule
- Targets a specific end user or workspace-wide
- Has failure handling rules and output routing

## Artifact
- Produced by a run
- Can be a document, code, structured data, image
- Stored and retrievable for the lifetime of the run

## Rating
- Captured via SDK from end users (1-5 scale)
- Tied to a specific run
- Flows back to the analytics agent

## Insight
- Generated by the analytics agent
- Tied to a workspace
- Has a category (capability gap, tier optimization, quality issue, scheduled task health)
- Has affected entity references (user IDs, run IDs, agent IDs)

## Workspace Member
- Has a role (admin, editor, viewer)
- Has access scoped to specific resources within the workspace

## API Key
- Belongs to a workspace
- A non-human credential — developers embed it in their backend so the SDK can call us as the workspace
- Has a name, key prefix (visible portion), hashed secret (full key shown once on creation, never recoverable thereafter), scopes (closed set: `runs:write`, `runs:read`, `tools:read`, `knowledge:read`, `end_users:write`, `end_users:read`), creator (workspace member), last_used_at, revoked_at, expires_at (optional)
- Authorized by **scopes**, not roles — distinct from Workspace Member, which uses admin/editor/viewer
- Created and revoked by workspace admins; revocation is permanent (rotate by creating a new key)
